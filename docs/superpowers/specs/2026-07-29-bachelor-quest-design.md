# Квест на мальчишник — дизайн

Дата: 2026-07-29

## Цель

Мобильное веб-приложение — квест на мальчишник брата. Серия страниц: на
каждой загадка/задание, игрок вводит кодовое слово (или попадает по QR),
переходит на следующий этап. Разворачивается на GitHub Pages.

## Ограничения и решения

- **Хостинг:** GitHub Pages (статика, всё исполняется на клиенте).
- **Без сборки:** vanilla JS/CSS/HTML, GitHub Pages отдаёт файлы напрямую.
  TS-болванка под Node (`src/index.ts`, `tsconfig.json`, CommonJS) удаляется —
  для статики не нужна.
- **Защита:** отсутствует (вариант A). Квест линейный, доверяем игрокам.
  Коды и QR-ссылки видны в исходнике — для мальчишника приемлемо.
- **Взаимодействие:** основные — ввод кодового слова (A) и QR-ссылки (C).
  QR не отдельный тип, а способ *попасть* на этап. Тип D (фото/гео/таймер/
  головоломка) — задел на будущее через поле `type`, сейчас не реализуется.
- **Этапов:** 5.
- **Язык интерфейса:** русский.
- **Мобильный приоритет:** mobile-first, тёмная тема.

## Архитектура

```
index.html        # каркас: контейнер #app, подключение CSS/JS
css/styles.css    # mobile-first стили, тёмная тема
js/stages.js      # ДАННЫЕ квеста — массив этапов (правится тут)
js/quest.js       # логика: hash-роутинг, рендер, проверка кода
qr/               # (опц.) сгенерированные PNG QR-кодов для печати
img/              # (опц.) картинки-подсказки
```

Разделение ответственности:
- `stages.js` — только данные. Контент квеста в одном месте (правка загадок,
  кодов, текстов без касания логики).
- `quest.js` — только поведение. Не содержит контента.
- `styles.css` — только оформление.

## Модель данных (один этап)

```js
{
  id: 2,
  title: "Этап 2",
  riddle: "Текст загадки / задания (HTML разрешён)",
  image: "img/clue2.jpg",     // опционально
  answer: "коляныч",          // код-слово
  next: 3,                    // id следующего этапа
  hint: "Подсказка",          // опционально
  wrongTexts: [               // опционально; на неверный ответ — случайный из массива
    "Не, брат, думай ещё 🍺",
    "Мимо! Ещё по одной и попробуй",
    "Холодно…"
  ],
  correctText: "Верно! Держи путь к следующей точке 🎯"  // текст после верного ответа
}
```

Правила полей:
- `answer` — сверка нормализованная: `trim()` + `toLowerCase()` с обеих сторон.
- `wrongTexts` пуст/отсутствует → дефолт «Не то, попробуй ещё».
- `correctText` отсутствует → дефолт «Верно!».
- `next` отсутствует → этап считается последним (финальный экран).
- `image`, `hint` — опциональны, рендерятся при наличии.

## Роутинг

- Hash-роутинг: `…/#/stage/<id>`.
- QR-ссылки указывают на полный URL этапа:
  `https://<user>.github.io/<repo>/#/stage/3`.
- `index.html` открыт без hash → редирект на `#/stage/1`.
- Hash с несуществующим `id` (напр. `#/stage/99`) → редирект на этап 1.

## Поток прохождения

1. Открытие `…/#/stage/N` → рендер: `title`, `riddle`, `image` (если есть),
   поле ввода кода, кнопка проверки, `hint` (если есть, за раскрытием).
2. Ввод кода → нормализация → сверка с `answer`.
3. **Верно:**
   - поле ввода и кнопка проверки скрываются,
   - показывается `correctText`,
   - появляется кнопка **«Дальше →»**,
   - тап по кнопке → смена hash на `next`, анимация перехода.
   - Автоперехода нет — гость сам читает и жмёт.
4. **Неверно:**
   - тряска поля ввода,
   - показ случайного текста из `wrongTexts` (или дефолт),
   - поле не очищается.
5. **Последний этап** (`next` отсутствует) → финальный экран
   (поздравление / адрес места сбора).

## Обработка ошибок / краёв

- Неверный код → тряска + `wrongTexts`/дефолт, ввод сохраняется.
- Пустой ввод → кнопка проверки неактивна, ничего не происходит.
- Битый/несуществующий hash → редирект на этап 1.

## Оформление

- Mobile-first, тёмная тема.
- Крупные тапабельные элементы (поле ввода, кнопки).
- Анимации: тряска поля при ошибке, плавный переход между этапами.
- Конкретная палитра/шрифт/фон — на этапе вёрстки (тема мальчишника пока
  не задана; по умолчанию — на усмотрение, уточняется при реализации).

## QR-коды

- Ссылка QR = полный URL этапа (см. Роутинг).
- PNG генерятся заранее, кладутся в `qr/`, печатаются, прячутся в реале.
- Способ генерации (скрипт или онлайн-сервис) — на этапе реализации.

## Явно вне объёма (YAGNI)

- Фреймворки (React/Vite) — оверкилл для 5 статичных этапов.
- Серверная логика, БД, авторизация.
- Защита от перескока, хэширование кодов, localStorage-прогресс.
- Взаимодействия типа D — задел, не реализуется сейчас.

## Открытые вопросы (не блокируют реализацию)

- Тема оформления (цвета/шрифт).
- Финальные тексты загадок и кодов (дорабатываются по ходу — вариант B).
- Конкретные D-взаимодействия (возможно, позже).
